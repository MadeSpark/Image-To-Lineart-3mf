## 光映浮雕几何第 12 轮定案：▼ 反向堆叠彻底删除，改为「柱体坐在 A 面底板上」

### 起因：审计发现第 11 轮「倒扣即可无支撑」结论是错的
第 11 轮只验了 `B面透光浮雕` 单个网格就下了"倒扣后 SHRINKING、floating=0、免支撑"的结论。
写临时审计脚本 `tmp_flipPrintAudit.test.ts` 对整个组合体做逐层审计后发现：

- 背景下层（实心满铺底座，导出时**无条件包含**）倒扣后必然被甩到顶部变成悬顶
- **第一层 87.5% 悬空**，下方空腔平均 0.848mm、最大 1.35mm
- 4225 根柱子里 **0 根**真正顶到底板（只有纯黑柱够得着）
- 与此同时还查出测试盲区：老测试传 `baseLoops: []`，背景下层退化成 **0 顶点空网格**，
  而 `expect(parsed['背景下层']).toBeTruthy()` 对空数组 `[]` **也是真值** → 断言形同虚设

### 结构性死结（绕不过去）
硬约束：**免支撑 ⟹ 截面随 Z 单调不增 ⟹ 承载图像的凹凸面必须在外面朝上**。
▼ 要求尖端朝下贴 A 面 → 必须倒扣 → 一倒扣，A 面底板就变成悬在空腔上的天花板。
「实心底板 + 空腔 + 实心浮雕」三明治，无论怎么翻转都有一头悬空。
另外两条看似聪明的出路都是死路：填平空腔 → 各柱等厚 → 图像消失；每根柱尖都贴 A 面 → 各柱等高 → 同样无图像。

### 最终方案（用户拍板思路：浮雕底面齐平贴死 A 面 + 顶盖无条件删除）
1. `buildHalftoneReliefMesh`：删掉 `reverseStack` 参数与 ▼ 分支，固定为
   `bottom = zStart`（齐平）、`top = zStart + avgH`（随灰度起伏）。函数注释写清三轮被推翻的理由。
2. **背景顶层（顶盖）永久删除**（原本是 `omitTopCover = reverseStack`，只有 ▼ 才省）。
   顶盖盖在凹凸面上方，只有最高峰顶得到，谷底上方全空腔 → 悬顶 + 挡光。这正是用户上次说的
   "我不是让你删除浮雕的顶板吗"。导出与预览两处都删。
3. 删除 3MF `<item>` 的 180° X 轴翻转 transform，以及预览里的倒扣翻转循环。
   预览朝向 = 导出朝向 = 可打印朝向。
4. 彻底移除 `bFaceReverseStack` 开关：`types/generator.ts`、`generatorStore.ts` 默认值、
   `LightReliefPanel.tsx` 的 checkbox + 提示块（替换为静态说明文字）。
5. schema v4 迁移：删除老快照里残留的 `lightReliefSettings.bFaceReverseStack`。

### 测试改动

  顶盖必须 undefined + 浮雕底面 min/max 都贴死底板顶面 + 整组合体悬空率 < 2%）。
- 删除 `reverseStack3mfExport.test.ts`（整文件测 ▼/▲ 双形态，已全部过时）与临时审计文件。
- `generator.test.ts`：原双形态断言 → 单形态「柱体贴死底板 + 永不打顶盖」。

## 光映浮雕高度图分辨率封顶（2026-08-31 后续）

### 起因：第二个结构性问题（与几何无关，但与可交付性强相关）
`buildHalftoneReliefMesh` 的 `pixelsPerMm` 参数**是死参数**（声明了但函数体没用），
浮雕网格规模完全由高度图 W/H 决定。而高度图走 `choosePixelsPerMm`，对 150×100mm 板给 8px/mm
→ 1200×800 网格 → 385 万三角面 / 约 250MB XML / 约 27MB 3MF。
0.125mm 格距比 0.4mm 喷嘴细 3.2 倍，绝大多数几何打印机复现不出来。
更糟的是 `choosePixelsPerMm` 下限硬夹 4px/mm，板子超 ~300mm 后封顶失效：
500×500mm 板 → 2000×2000 格 → 1600 万三角面 → 约 1.1GB XML → 超出 V8 字符串上限（536,870,888）直接崩。

### 方案（用户拍板：0.2mm/格）
1. `buildHalftoneReliefMesh` 删掉死参数 `pixelsPerMm`，内部统一调用 `capHalftoneHeightMapDensity`。
2. 新增密度上限 `RELIEF_CELLS_PER_MM = 5`（即 0.2mm/格）+ 绝对格数上限 `RELIEF_MAX_CELLS = 720_000`
   （兜底超大画板，720K 格 ≈ 196MB XML，距 V8 上限约 2.7 倍余量）。
3. 降采样用**盒式平均**（不是抽样），细密图案（棋盘）收敛为均匀灰、不产生摩尔纹。
4. 封顶放在建网格之前 → 导出与 3D 预览共用同一份高度图，所见即所得不破。

### 测试改动
- `reliefSliceDiagnostic.test.ts` 新增 3 条：密度封顶（150×100mm 1200×800→750×500）、
  绝对格数兜底（500×500mm 2000×2000→848×848）、盒式平均无摩尔纹（棋盘→均匀 z）。
- 测试辅助 `readCols` 去掉已删的 `pixelsPerMm` 参数。

### 结果
`npm run build` 通过；**70 条测试全过（12 文件，含 realImageLineDebug 那条 167s 的真实图管线测试）**。
实测：150×100mm 面数降 61%（385万→151万），500×500mm 从 1600 万面降到 288 万面。

### 教训（并入 MEMORY.md）
- 凡是"导出网格规模"都要有**密度 + 绝对格数双重封顶**，单靠密度封顶会在源分辨率变粗时失效。
- 函数签名里的死参数会**误导审查**（以为是按源分辨率来的），删死参数比留着更安全。
- 性能/规模风险用**真实端到端导出**实测（体积 + 耗时 + 压缩比），比按顶点数估算的 XML 上界更准确
  （zip 实测压缩比约 9:1，真实 3MF 比 XML 上界温和得多）。
