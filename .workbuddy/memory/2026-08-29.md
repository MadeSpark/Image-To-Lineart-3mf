## 一、最小线宽「过度膨胀」修复（用户反馈：预览 0.4mm / 切片两条线 / 打印 > 1mm）

### 根因
`applyMinimumLineWidth` 旧公式 `dilate by ceil((minWidth*pxPerMm - 1) * 0.5)` 是按"最坏 1px 输入"
反推的**全局膨胀**——对所有线一律加粗 2px。实测（6.93 px/mm, minWidth=0.4mm）：
1px→3px(0.43mm) / 2px→4px / 3px→5px(0.72mm) / 5px→7px(1.01mm)。
粗线被无故加粗 0.3-0.6mm，切片器要多铺 2-3 道喷嘴 → 用户实测塑料宽 > 1mm。

### 修复（两次迭代才对）
1. 第一次尝试（不够）：改用 Chebyshev 距离变换做"变半径膨胀"（每像素按 dist 补足）。
   失败原因：任何线的边缘像素 dist 恒为 1（紧贴背景），仍被判为"细"→ 照样连锁膨胀。
2. 第二次（正确）：改为 thick-component 判定 —— 用 `labelSolidComponents` 找连通域，
   只要域内任一像素 `dist >= minDistThreshold = ceil((minWidthPx+1)/2)`，整个域视为粗线，
   完全跳过膨胀；只有"无达标中心"的细线域才按 `dilateBy = ceil((minWidthPx - 2*maxDist)/2)`
   对整个域均匀膨胀。关键：同一域用同一个 dilateBy，避免边缘像素被推爆。
- 新增辅助函数 `chebyshevDistanceTransformBg`（2-pass Chamfer）。

### 效果（6.93 px/mm, minWidth=0.4mm）
1px→3px(0.43mm，1 道喷嘴) / 3px→3px / 5px→5px（原样保留，不再变 7px）。

### 改动文件
- `webapp/src/utils/generator.ts`：`applyMinimumLineWidth` 重写 + 新增 `chebyshevDistanceTransformBg`。
- `webapp/src/utils/generator.test.ts`：新增 4 个"不 over-dilate"用例（用 20 px/mm 的
  `hiResPxPerMm`）+ 新增 `measureLineThicknessAt` 辅助；旧「最小线宽保底」用例期望
  32-36px 改为 28-32px（粗条带不该被加粗）。

### 教训
- 测线宽要测"厚度"不是"长度"：第一版用"最长水平连续段"，量到的是线的长度（50px）。
  改用"指定 x 处的垂直连续段"。
- 测试分辨率 10 px/mm 太低，整数像素离散化会掩盖真实行为；新用例统一用 20 px/mm。

### 2b. 追加修正：悬挂基准应为「浮雕实际最高点」（用户给分层图示后定位）

- 导出 `buildHalftoneReliefMesh` 供测试；新增 2 个直接断言顶点 Z 分布的用例
  （正向=底面全平/顶面起伏；反向=顶面全平/底面起伏 + 实际最高点 < bFaceTopMm 证明留空）。
  均匀灰度旧用例断言同步改为 [0.6, 0.725]（等厚平板翻转仍原地，不再悬到 [0.675, 0.8]）。

### 4. 实现「删除顶层」——避免 stackTopZ 顶层 0.05mm 薄壳在切片顶层炒面（用户 8-29 截图 2 实证）
- **用户原话**：「为什么生成出的还有顶层？你是不是不知道我一直强调移除顶层的原因？因为浮雕反向堆叠后，假设有些地方只有2层，但是浮雕顶层在第4层，那么你说顶层打印的时候是不是就会悬空（炒面）」「这次我给你看了实际切片的图片，能理解为什么我非要删除浮雕的"顶面"了吗？」
- **我上一轮的理解错**了——用户说「我让你删除顶面没让你把外框也删了」其实**接受"删除顶面"**（要避免浅色区域炒面），只是要外框保留。我误读为"不要删除顶面"撤销了壳模式，结果 stackTopZ 顶层有浅色区域 0.05mm 薄壳 → 切片顶层炒面（用户截图 2 警告"浮空区域"）。
- **修复**（`buildHalftoneReliefMesh` reverseStack 分支）：
  1. 内容区顶面 = `max(bottomZ, stackTopZ - minThick)`——不打印 stackTopZ 顶层 minThick=0.05mm 厚度。
  2. 浅色区域（avgH ≤ minThick）自然退化为 0 厚度（不打印）→ 解决"浅色顶层炒面"。
  3. 中等列少 0.05mm 顶部（损失微小，避免炒面）。
  4. 外框**用 contentRect + data 显式判定**（不是 avgH）：顶点的 4 角 cell 中至少 1 个在 contentRect 外 + data ≥ 1-1e-5 才算外框；外框整列 `[zStart, stackTopZ]` 实心柱（保留满铺平面顶作为结构支撑）。
  5. stackTopZ 顶层只有外框有材料 → **顶层不炒面**。
- **外框判定不能用 `avgH >= maxHeightMm - 1e-5`** 的教训：占满动态范围的 heightMap 边界顶点
  （cell data=1，avgH = 0.2 = maxHeightMm）会被误判为外框，但实际它不是"安全边距外框"
  （用户没设 padding）。**必须用 contentRect + data 显式区分**。
- 已知代价：均匀灰度平板翻转后厚度比正向少 0.05mm（normalThickness - minThick）——
  这是"删除顶层"必然的代价。
- 已知副作用：bumpy 面谷底与背景下层之间的空隙（用户已知，需加支撑或调小 B 面高度）。
- 验证：tsc 通过 / vitest 64 项全过（11 文件）/ vite build 6.72s
  交付：`webapp/dist/index.html`（单文件）。

### 5. 「自测驱动」——发现并最终解决反向堆叠浮空（用户 8-29 截图 2 实证"Bambu 警告：浮空区域"）
- **用户原话**：「自己看吧，没任何区别，你给我自己测试代码导出验证没问题了再交任务」
  —— 配两张截图：Bambu 切片预览里浮雕 + 警告「似乎物件未被浮雕有序浮空区域」。
- **根因（之前测试没暴露的）**：上一轮"删除顶层"实现仍走 `bottom = max(zStart, stackTopZ - avgH)`，
  反向堆叠时浅色 (avgH=0.05) 列底面 = stackTopZ - 0.05 = 0.735，**底面浮在底座顶 0.6 之上 0.135 mm**；
  中等列 (avgH=0.125) 底面 = 0.66，**悬空 0.06 mm**。
  切片 layer 1 (Z=zStart~zStart+lh) 在这些 X-Y 位置打印耗材 → **底面下方是空气 → 炒面**。
- **自测驱动器 `reliefSliceDiagnostic.test.ts`**：构造不同高度图（含外框/纯内容/均匀灰度）调
  `buildHalftoneReliefMesh(reverseStack=true)` 后**逐层切片**（layerH=0.04 mm）检查每 (x,y) 列耗材
  底面是否 ≤ layerZ。**3 个用例全部"✓ 所有切片层均无浮空"** 才算交付。
- **最终实现：方案 B（用户选定）**：所有列底面贴 zStart，顶面削减 minThick。
  - 内容区浅色 (avgH ≤ minThick)：0 厚度退化（沉到 zStart）—— 浅色顶层不打印 → 不炒面
  - 内容区非浅色：bottom=zStart, top=zStart+max(minThick, avgH-minThick)（削减顶层 0.05mm）
  - 外框（contentRect 外 + data≥1）：整列 [zStart, stackTopZ] 实心边墙
  - stackTopZ 顶层只有外框耗材 → 顶层不炒面
- **关键验证**：所有内容列底面都贴底座 → layer 1 底面整片实心 → 无悬空 ✓
  切片诊断测试通过 + 全量 67 项测试通过（12 文件，含 164.4s 真实图管线测试）。
- **经历**：4 轮反复（壳模式 → 撤销壳模式 → 删除顶层+保留外框 → 方案 B），本轮次用真切片模拟器
  第一次从底面浮空发现 → 修复 → 切片验证 0 浮空。
- **教训**：
  1. "走相同函数" ≠ "参数对" ≠ "几何对"——必须**实际逐层模拟切片器**验证 Z 区间分布。
  2. 单元测试只检查 `bottomZs()`/`topZs()` 的最值，**不会发现"列底面 > layerZ"的悬空**——
     必须显式做"以 layer 为步长划 Z、对每片 (x,y) 查底面支撑"的检查。

### 6. 反向堆叠最终定义：▲ → ▼（用户 8-29 一句话点破，4 轮反复后定案）
- **用户原话**：「这反向堆叠开了和没开一样啊。。。我举个更简单的例子，假设没开反向堆叠时是▲那么在开启反向堆叠后就是▼」
- **我的错**：上一轮"方案 B"（底面平齐 zStart + 顶面削 minThick）形状仍是 ▲ —— 底面平、顶面起伏，
  只是矮了 0.05mm，所以用户说"开了和没开一样"。我误把"避免悬空/炒面"当成了主体，把翻转本身丢了。
- **正确实现**（`buildHalftoneReliefMesh` reverseStack 分支，短短 12 行）：
  ```
  const bottomZ = Math.max(zStart, stackTopZ - avgH)   // 起伏面朝下（bumpy 贴背景下层）
  if (avgH <= minThick + 1e-5) { bottom = top = stackTopZ }   // 最亮处 0 厚度，不留 0.05mm 悬空薄片
  else { bottom = bottomZ; top = stackTopZ }                   // 顶面满铺平面
  ```
  即镜像映射 z' = (zStart + stackTopZ) − z。外框（avgH > maxAvgH）镜像后穿到底座下 → 被 max() 钳位
  → 自动成为 [zStart, stackTopZ] 实心边墙。**不需要 isBorderCol/contentRect 判定**（方案 B 才需要）。
- **悬挂基准**仍用内容区实际最高点 maxAvgH（外框不计入），保证最深列贴 zStart、上方留空。
- **验证（端到端，两个新测试文件）**：
  1. `reliefSliceDiagnostic.test.ts`：断言 ▼ 是 ▲ 的严格镜像（除钳位列）、顶面齐平、底面起伏、

     因最亮处退化）。▼ 的 objects 里没有"背景顶层"（顶盖已省略）✓。
- **关键量化结论（重要，决定了使用方式）**：
  - ▼ 按原朝向打印：最差层 97.7% 悬垂、最大架空 0.16mm = 整整一个层高 → Bambu 报"浮空区域"。
