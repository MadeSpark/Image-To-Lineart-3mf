## 3MF 切片"眼睛细节消失"问题排查与修复

**用户反馈**：上一版（删除 printSafe + 预览改位图后）实际导出的 3MF 在切片器里看眼睛比 webapp 2D 预览糊。

**根因分析**（代码验证）：
- webapp 2D 预览 bitmap 和 3MF 网格用的是**完全相同的算法**——`rasterizeLoopsToMask` + `applyMinimumLineWidth(0.4)`，参数也一样。
- 3MF 网格里"眼睛白"是真实孔洞，但**切片器在 3D 预览里把孔洞渲染成底板颜色（灰）**，所以视觉上"细节消失"。实际打印时用白色耗材，眼睛白会显示成白色。

**修复**（两个独立改进）：
1. **3MF 包嵌入 plate 缩略图**（`Metadata/plate_1.png`）——把 composite 预览（底板+线稿）作为缩略图塞进 3MF 压缩包。切片器在文件浏览器会显示这张图，用户能直接看到眼睛等细节是否清晰，不再依赖切片器的 3D 预览（其会把孔洞渲成灰色）。
   - 新增 `dataUrlToPngBytes()` 辅助函数（Node/浏览器双路径）。
   - `build3mfPackage` / `buildSeal3mfZipPackage` / `buildLightRelief3mfPackage` 三个导出路径都加。
   - 封口参数：`compositeThumbnailPng?: Uint8Array | null` 透传给 `buildSeal3mfZipPackage`。
   - 新增测试 `embeds composite preview as plate thumbnail when available`：用 1x1 PNG 验证 PNG 魔数 (89 50 4E 47) 出现在 zip 内。

2. **导出分辨率上限提高**（`chooseSingleExportPixelsPerMm`）：
   - 旧：`maxSingleDimensionPx = 960`、`maxSingleAreaPx = 420_000` → 150x100mm 板上 5.29 px/mm
   - 新：`maxSingleDimensionPx = 1280`、`maxSingleAreaPx = 720_000` → 150x100mm 板上 **6.93 px/mm**（+31%）
   - 副作用：3MF 文件体积 +约 70%，但能给切片器留更多眼睛像素，缓解"切片器预览里看糊"的问题。
   - 同步更新 `generator.test.ts` 的硬编码断言（420_000 → 720_000）。

## 第二轮：找到真正的预览/3MF 差异根因并彻底统一掩码管线

**触发**：上一版（缩略图+分辨率提升）交付后用户再反馈"依旧不行，和预览差得多了"并附切片器截图。

**真正根因**（上一版结论"算法相同只是切片器渲染差异"是错的）：
- `shapeLoopsForPrintPreview`（2D 预览位图）只做 rasterize → applyMinimumLineWidth，**漏掉了 加粗/缩小描边 两步**。
- `extrudeMaskToMesh`（3MF 网格）做 rasterize → 缩小腐蚀 → 加粗膨胀 → applyMinimumLineWidth。
- 用户设了 `shrinkStrokeMm`（缩小描边）时，3MF 里的细小特征（瞳孔、高光）会被腐蚀整体删除，而预览位图完全显示——预览与 3MF 出现肉眼可见差异，正是用户看到的"差得远了"。
- `UploadPanel.tsx` UI 文案承诺"缩小描边受最小线宽限制、过度缩小不低于打印线宽下限"，但旧腐蚀逻辑只在全局保 10% 填充量，**不保局部小特征**——承诺未兑现。

**修复**（generator.ts）：
1. **抽取统一管线** `buildExportLineMask(loops, W, H, pxPerMm, minLineWidth, expand, shrink)`：rasterize → 缩小腐蚀（含过度腐蚀防护）→ 加粗膨胀 → applyMinimumLineWidth。`extrudeMaskToMesh` 与 `shapeLoopsForPrintPreview` **都改调它**，预览与 3MF 自此逐像素一致。导出此函数供测试。
2. **消失组件救援** `rescueVanishedComponents` + `labelSolidComponents`（8 连通域标记）：腐蚀后逐连通域检查，完全被吞掉的组件（瞳孔/高光等）以原始像素救回，最终由 applyMinimumLineWidth 保底到最小线宽——兑现 UI 承诺"缩小描边不删细节、不低于下限"。
3. **调用点传参**：`processArtwork` 预览传 `lineartSettings.expandStrokeMm/shrinkStrokeMm`；`rebuildArtworkWithLineLoops` / `applyNumberartStrokeEdit` / `applyNumberingToArtwork` 加 `strokeOptions?: LineartStrokeMaskOptions` 参数（导出 interface）；`Home.tsx` 三处调用 + brush 编辑都传 `lineartStrokeOptions`（useMemo 含 minLineWidth/expand/shrink）。

**验证**（决定性证据）：
- 把 `realImageLineDebug.test.ts` 的"3MF 侧"从测试自绘 canvas 模拟改成**直接调真实 `buildExportLineMask`**。结果：`_testimg.png`（150×100mm，6.93px/mm）预览位图 vs 3MF 真实管线 mask **差异 0.00%**（此前测试模拟显示的 21.3% 是测试自绘光栅化与真实管线取样方式不同的**测试假象**，浏览器里两者都用同一函数本就一致）。
- 新增 4 个 `buildExportLineMask` 单元测试：小细节救援、腐蚀生效、最小线宽保底（30px→dilate2→34px）、加粗膨胀。
- 全部 11 个测试文件逐一运行全过；类型检查通过；`npm run build` 成功（dist/index.html 667 KB）。
- 注意：`npx vitest run`（全量并发）在沙箱里静默退出（OOM），逐文件运行无问题——非代码问题。

## 关键教训
- "代码看起来走相同函数"不等于"参数相同"——必须逐个对比传参，`shapeLoopsForPrintPreview` 之前少传 expand/shrink 就是 bug 源头。
- 真实图像端到端 parity 测试（用真实导出函数而非测试自绘模拟）是验证 WYSIWYG 的唯一可靠手段；测试自绘模拟会引入与真实实现不同的取样方式，产生假象/漏检。

## 第三轮：优化"缩小描边"——拉满也不缺失，窄于下限按下限

**用户要求**：缩小描边原本设想"处理后线宽 < 最小线宽时按最小线宽算"，但之前没实现，导致拉大缩小描边时线稿结构缺失（不是"按 0.4 算"）。要求：即使拉满缩小描边也不能出现线稿结构缺失，只出现"缩小后的理想图像"（窄于最小线宽的按最小线宽、宽于的照常缩小）。

**残存根因**（上一轮 `rescueVanishedComponents` 仍不够）：
- `buildExportLineMask` 的缩小段有个 `while` + **10% 全局填充率回退守卫**：拉大缩小描边时会逐级回退腐蚀半径（甚至跳过腐蚀），所以"缩小"实际被削弱/失效；且守卫只保全局填充总量，不保单个小特征（瞳孔/高光/细线照样被整体删除）。
- `rescueVanishedComponents` 当时只救"完全消失"的组件，不处理"线条被掐断成两截"的断裂情形（断裂也是一种结构缺失）。

**修复**（generator.ts）：
1. **去掉全局回退守卫**，缩小描边按用户设定的**完整半径**腐蚀——真正缩小生效。
2. **重写 `rescueVanishedComponents`**：逐连通域比对"原始组件 ↔ 腐蚀后子组件"映射：
   - 映射到恰好 1 个子组件 → 存活且连续，保留腐蚀结果（真正缩小形态）；
   - 映射到 0 个（整体消失）或 >1 个（被掐断）→ 该原始组件以原始像素救回；
   - 最小线宽保底交给下游唯一一次 `applyMinimumLineWidth`（救援函数自身不再膨胀，避免双重保底把线加粗过头）。
   - 这样"消失"和"断裂"两种结构缺失都不再发生。
3. **3D GLTF 预览路径**（`buildPreviewModelGltfBlob` 内，~原 line 3110）原本也有同样的 `while`+15% 守卫，一并改为完整半径腐蚀 + `rescueVanishedComponents`（min=0，仅做不缺失救援；最小线宽下限在 3D 导出阶段由 `applyMinimumLineWidth` 强制）。保证 App 内 3D 预览也不丢结构。

**验证**：

- `generator.test.ts` 28 个、realImageLineDebug parity（0.00%）、lineWidthConsistency 4 个、baseplate/color/canvasBounds/importLimits/threeMfProfile 共 15 个——全部通过 ✅
